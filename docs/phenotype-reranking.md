# HCM: отдельное ранжирование по полным транскриптам

`scripts/rerank_phenotype_candidates.py` читает четыре завершённых индивидуальных master из закрытого основного набора. Каждый master содержит полные строки для наблюдавшихся ALT. Это отдельный локальный исследовательский отчёт: исходные VCF, master, top-20 и ранги не заменяются. VEP, calling и внешние API не запускаются.

```powershell
python scripts/rerank_phenotype_candidates.py --views "$env:LOCAL_COHORT_VIEWS" --clinical-profiles "$env:CLINICAL_PROFILES" --hpo-genes "$env:HPO_GENE_ASSOCIATIONS" --clingen-validity "$env:CLINGEN_VALIDITY" --output "$env:NEW_HCM_OUTPUT" --workers 4
python scripts/rerank_phenotype_candidates.py --views "$env:LOCAL_COHORT_VIEWS" --clinical-profiles "$env:CLINICAL_PROFILES" --hpo-genes "$env:HPO_GENE_ASSOCIATIONS" --clingen-validity "$env:CLINGEN_VALIDITY" --output "$env:NEW_HCM_OUTPUT" --workers 4 --max-hours 8 --execute
```

Без `--execute` выполняется только проверка небольших метаданных, размеров и клинического профиля. Полные master не сканируются и выход не создаётся. Для выполнения нужна новая пустая папка вне исходной выдачи. Максимум — четыре отдельных процесса и восемь часов.

## Подтверждённый клинический контекст

Поддерживается приватный JSON schema_version=1 с `created_utc`, `assertion_source` и списком `samples`. Каждая запись содержит `sample_id`, `diagnoses` с label Hypertrophic cardiomyopathy или mondo_id MONDO:0005045 и confirmation=confirmed_by_user; `phenotypic_features` содержит hpo_id HP:0001639, status=present, source=user_report. Все четыре исходных образца должны присутствовать ровно один раз. Это сообщение пользователя о диагнозе; инструмент не подтверждает его независимыми клиническими документами. Другие поля профиля сохраняются для происхождения, но пол, родство, наследование и семейная история не выводятся из данных.

Также поддерживается явно документированный словарь `samples` с ключами идентификаторов и полями confirmed_hcm=true, hpo_terms, confirmation_source, confirmed_utc. Нет автоматического предположения HCM при пустом или неизвестном профиле.

## Полные транскрипты и качество

Сканируются все строки каждого индивидуального master. Подходящая строка должна одновременно иметь исходные candidate_eligible=1, quality_rank=1 и sample_state=alternate. Каждая подходящая транскриптная строка сохраняется целиком в `transcript-evidence/sample_000N.eligible-transcripts.jsonl`; исходные поля и ранги остаются строковыми значениями без изменения. Среди транскриптов одного точного аллеля и образца выбирается лучший по новому контексту. Поэтому подходящий HCM-ген второго транскрипта не теряется из-за прежнего представительного гена.

Счётчики уникальных подходящих аллелей каждого образца сверяются с manifest. Число прочитанных строк сверяется с sample_master_rows; сумма этих ALT-строк отличается от master_transcript_rows общего master, который также содержит референсные и отсутствующие генотипы. Общий счётчик сохраняется отдельно как исходная authority; равенство разных областей не заявляется. Число кандидатов в cohort/shared_ge2/all4 также должно совпасть с исходным manifest.

## Новый порядок

Положительный фенотипный контекст — точная связь гена с HPO HP:0001639 либо положительная ClinGen HCM validity: Definitive=3, Strong=2, Moderate=1. Для ClinGen требуется точный MONDO:0005045 либо каноническая фраза `hypertrophic cardiomyopathy` с границами слов по пробелам. Familial и другие явные подтипы с этой фразой сохраняются; просто другая кардиомиопатия не подходит. Учитывается точный символ гена и, когда доступны оба, совпадение HGNC ID.

Limited, Disputed, Refuted, No Known Disease Relationship и другие слабые/отрицательные записи сохраняются как доказательства с нулевым положительным validity rank. Их наличие само по себе не повышает фенотипный приоритет. HPO-связь шире согласованной генной панели и не доказывает причинность. Все подходящие ClinGen curation, включая MOI и разные варианты наследования, сохраняются; максимальный gene-disease rank не является genotype-aware заключением.

Порядок: новый положительный фенотипный контекст → новый ClinGen HCM validity rank → прежний lexicographic rank без старых phenotype/target/gene-validity измерений. Остальные размеры исходного ранга и детерминированные allele/gene/transcript/sample tie-breakers сохранены. Исходные rank-поля не редактируются; новые поля имеют префикс hcm_.

## Общие аллели и выходы

Исходная `allele-membership-matrix.tsv.gz` сохраняет полные вызовы четырёх образцов. Общность определяется одинаковыми CHROM/POS/REF/ALT, а не совпадением гена. Для shared_ge2 нужны минимум два исходных QC-носителя и хотя бы один исходный подходящий образец; для all4 — четыре QC-носителя и хотя бы один подходящий. Это не требование сделать каждого носителя подходящим.

Выдаются семь областей: cohort, shared_ge2, all4 и четыре индивидуальных набора:

- `tables/<scope>.all-candidates.tsv.gz` — все прежние кандидаты, пересортированные по новому контексту;
- `tables/<scope>.hcm-top20.tsv` и `.json` — только положительный HCM-контекст, максимум 20, без дополнения нерелевантными строками;
- `functional/<scope>/` и `functional-category-index.tsv` — ранжированные категории по объединению последствий исходных подходящих транскриптов точного аллеля; прежние полные функциональные таблицы не изменяются;
- `workbook-data.json` — summary, семь top-20 scopes и sources для отдельной Excel-выдачи;
- `manifest.json`, `clinical-profile-provenance.json`, `progress/` — происхождение и небольшие счётчики каждые 250 тысяч строк.

Если положительных HCM-кандидатов в области нет, её HCM top-20 пуст, но полная очередь остальных кандидатов сохраняется. Совпадение или отсутствие фенотипного контекста не означает pathogenic/benign.

ACMG остаётся NOT_ASSIGNED, критерии требуют ручных доказательств. PP4/PVS1, LoF/GoF, NMD, наследование, клиническая тяжесть и функциональная нагрузка автоматически не назначаются. Отсутствующая AF сохраняется пустой; высокая исходная AF рядом с внешним pathogenic label и конфликты ClinVar получают флаг ручной проверки, без автоматической переклассификации.

Исходные master проверяются по неизменности размера/mtime, без нового хеширования пациентских файлов. Для общего кода и публичных HPO/ClinGen источников записываются SHA. Результат сохраняется отдельно после сверки счётчиков; частичная папка не является завершённым отчётом.

## Excel и митохондриальное приложение

Необязательный `scripts/build_phenotype_workbook.mjs` формирует Excel из завершённого `workbook-data.json`. Нужен Node.js с bundled `@oai/artifact-tool`, доступным через Codex workspace dependencies. Основные TSV/JSON и Python-ранжирование от этой зависимости не зависят.

```powershell
node scripts/build_phenotype_workbook.mjs "$env:NEW_HCM_OUTPUT/workbook-data.json" "$env:NEW_XLSX_PATH" "$env:NEW_PREVIEW_DIRECTORY" "$env:NEW_MT_CONTEXT_OUTPUT/review.json"
```

Четвёртый аргумент необязателен и добавляет отдельный лист MT без клинического ранга. Листы содержат общий HCM top-20, одинаковые аллели минимум у двух/всех четырёх образцов и четыре индивидуальных HCM top-20. Число строк может быть меньше 20 или равно нулю; полные очереди остальных кандидатов остаются в TSV. Краткие листы не заменяют полные транскриптные JSONL/TSV-доказательства. Референсные идентификаторы и HGVS сохраняются текстом, числа и AF — числовыми значениями; пропуски не заменяются нулями.
