# HTTP-восстановление master: отдельное окно v2

`transfer/recover_master_http_segments_v2.py` содержит тот же проверенный приёмник недостающих ZIP-сегментов, что [v1](master-http-segment-recovery.md). Единственное изменение кода — абсолютный верхний срок 2026-11-06T07:30:00Z вместо 07:10. Это новое явно разрешённое окно переноса, а не изменение старого SFTP-плана или прежнего профиля.

```powershell
python transfer/recover_master_http_segments_v2.py --profile "$env:HTTP_RECOVERY_V2_PROFILE" --profile-sha256 "$env:HTTP_RECOVERY_V2_PROFILE_SHA256"
python transfer/recover_master_http_segments_v2.py --profile "$env:HTTP_RECOVERY_V2_PROFILE" --profile-sha256 "$env:HTTP_RECOVERY_V2_PROFILE_SHA256" --execute --watch
```

Нужен отдельно проверенный приватный профиль с точным новым producer SHA и новой папкой состояния. До запуска прежние SFTP/HTTP-процессы должны завершиться естественно либо весь набор уже должен иметь подтверждённое завершение. Повторно использованный живым процессом PID блокирует продолжение. Программа не останавливает процессы и не меняет исходные планы, код или профили.

Если используются собственные старые 32 MiB checkpoints, их сначала отдельно проверяют под той же блокировкой dataset.lock (байт 0): источник, исходный снимок missing set, полный набор полей каждого сегмента, CRC-флаг и границы должны совпасть с закрытым HTTP manifest. Живой 64 MiB bitmap должен точно соответствовать первоначально завершённым блокам плюс полностью подтверждённым парам. Старые журналы сохраняются; новая копия progress связывается с новым профилем и metadata SHA прежних профиля/журнала. Непроверенный журнал автоматически не принимается. Сам приёмник не выполняет такое перепривязывание самостоятельно.

Остальные защиты v1 сохранены: только первоначально недостающие диапазоны, точный собственный inode и физически выделенный размер, ZIP_STORED с двумя закрытыми членами, проверка всех CRC до записи, fsync до checkpoint, запрет перезаписи завершённых блоков и готового final. Большой master не хешируется заново; ожидаемый серверный SHA остаётся происхождением SIZE ONLY.

Наличие запущенного v2 не означает готовый набор. Завершение подтверждается только COMPLETED_CLOSED_DATASET_SIZE_ONLY_HTTP_RECOVERY с whole_dataset_complete=true после всех сегментов и проверки всех квитанций. При ошибке или новом сроке собственные файлы и журналы сохраняются без автоматического перезапуска. Аннотация, клинические поля, ACMG и данные других образцов не пересчитываются.

Старый receiver v1 и его публикационные снимки остаются неизменными. Приватные профили, process IDs, источник сегментов и миграционные доказательства не входят в общий репозиторий.
