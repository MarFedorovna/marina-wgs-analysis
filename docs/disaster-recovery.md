# Восстановление проекта

## Минимальный тест восстановления

Раз в месяц и после каждого крупного snapshot:

1. клонировать GitHub-репозиторий в новый пустой каталог;
2. проверить tag/commit, документацию и синтаксис скриптов;
3. выбрать один небольшой приватный результат и сверить SHA-256 с manifest;
4. проверить чтение одного BAM+индекса и одного VCF+индекса;
5. открыть Excel/Word/HTML из backup-копии;
6. записать дату, проверенную копию и результат теста.

## Порядок восстановления после потери компьютера

1. Клонировать GitHub по зафиксированному tag.
2. Восстановить private data snapshot с облачной или холодной копии.
3. Проверить private manifest до запуска анализа.
4. Восстановить конфигурации вне Git и проверить reference/resource SHA-256.
5. Продолжить только с последней контрольной точки `PASS`; частичный этап не считать завершённым.

## Порядок после потери облачного сервера

Если локально скопированы BAM/gVCF/cohort VCF и receipts, продолжить с последней проверенной точки. Если серверные выходы не были скопированы, воспроизвести этап от последнего сохранённого входа. Утверждение в сообщении или README не заменяет фактический output package.
