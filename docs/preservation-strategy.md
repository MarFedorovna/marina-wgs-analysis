# Сохранность проекта: код, результаты и исходные данные

## Цель

Ни один носитель не считается единственной копией. Проект сохраняется по правилу 3-2-1:

- минимум три проверенные копии;
- минимум два разных типа хранения;
- минимум одна копия вне рабочего компьютера.

GitHub хранит код, документацию, обезличенные шаблоны конфигураций и историю решений. FASTQ, BAM, gVCF, VCF, клинические таблицы, реальные manifests, логи с путями и любые ключи остаются вне GitHub.

## Рекомендуемые копии

| Копия | Назначение | Содержимое | Проверка |
|---|---|---|---|
| Рабочая | ежедневная работа | полный проект | SHA-256 manifest после значимого этапа |
| Облачная | совместный доступ и off-site backup | зашифрованные исходные данные и структурированные результаты | сверка размеров и SHA-256 после загрузки |
| Холодная | восстановление после удаления/блокировки аккаунта | полный snapshot на отдельном SSD | отключённый после записи носитель, тест чтения |
| GitHub | воспроизводимость | код, документация, публичные manifests без идентификаторов | commit, signed/annotated tag, remote clone test |

Google Drive не заменяет отдельную холодную копию: синхронизация может распространить случайное удаление. GitHub не заменяет хранилище геномных данных.

## Контрольные точки

Создавать snapshot после:

1. получения и проверки исходных FASTQ;
2. завершения BAM/QC;
3. завершения gVCF;
4. совместного генотипирования;
5. фильтрации;
6. аннотации;
7. замораживания списка кандидатов;
8. экспертного ACMG;
9. каждой версии рукописи, переданной научному руководителю;
10. подачи и принятия статьи.

Каждая точка содержит README, manifest SHA-256, версии инструментов, конфигурацию, журналы команд, выходы и статус `complete` либо `partial`. Один только ZIP без manifest не считается проверенной копией.

## Имена snapshot

Формат:

`YYYY-MM-DD_analysis-stage_status`

Примеры:

- `2026-11-05_analysis1-legacy_frozen`
- `2026-11-05_analysis2-joint_partial`
- `2026-11-20_analysis2-annotation_complete`

Snapshot после публикации должен включать DOI, принятую рукопись, supplementary materials, финальный код и точные версии баз.

## Что запрещено коммитить

- FASTQ/FASTA пациента, BAM/CRAM/SAM;
- gVCF/VCF/BCF и индексы;
- phenotype/clinical tables и consent/ethics records;
- реальные sample manifests, пути, IP/SSH-конфигурации;
- токены, ключи и credentials;
- логи, содержащие реальные имена файлов или идентификаторы.

Перед каждым push выполнять `scripts/audit_git_payload.py --staged`.
