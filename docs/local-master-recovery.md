# Восстановление master из локального VCF

`transfer/rebuild_local_cohort_master.py` работает чистым Python на Windows, без сети, базы данных, VEP или новых прогнозов. Уже сохранённый общий VCF содержит 138 полей строк и аллельный SpliceAI INFO. Тот же закреплённый кодек проецирует ещё 13 полей: итоговый master имеет 151 поле. Все строки и генотипы сохраняются в исходном порядке; фильтрация, ранжирование и ACMG не выполняются.

По умолчанию читается только ограниченный префикс: максимум 10 аллелей и 32 MiB сжатых данных. Выходной master не создаётся.

```powershell
& "$env:NATIVE_SFTP_PYTHON" transfer/rebuild_local_cohort_master.py --vcf "$env:LOCAL_FULLY_ANNOTATED_VCF" --views-manifest "$env:LOCAL_VIEWS_MANIFEST"
```

Полное восстановление запускается отдельно только после проверки нового кода и выбранного выхода:

```powershell
& "$env:NATIVE_SFTP_PYTHON" transfer/rebuild_local_cohort_master.py --vcf "$env:LOCAL_FULLY_ANNOTATED_VCF" --views-manifest "$env:LOCAL_VIEWS_MANIFEST" --output "$env:NEW_RECONSTRUCTED_MASTER_DIR" --workers 6 --max-hours 8 --execute
```

Выход — новая отдельная папка, например `Reports/cohort-master-reconstructed-v1`. Исходный VCF, действующий перенос, его `.part` и полный набор `cohort-sample-views-v1` не изменяются. Локальные пути и значения подключения в код не вставляются. Для этого инструмента конфигурация подключения вообще не нужна.

Источник связывается с существующей квитанцией COMPLETED_SIZE_ONLY: ожидаемый серверный SHA, локальные размер и mtime должны совпасть с completed view manifest. Большой исходный VCF заново не хешируется. Кодеки и pure projection закреплены своими SHA. Перечень и порядок полей сверяются с logical_full_fields.

Для каждого исходного блока проверяются точные глобальные порядковые номера, число строк/аллелей и канонический digest сохранённых 138 полей. Затем формируется digest полных 151 полей с теми же границами блока. Итоговый ordered-batch Merkle должен совпасть с derived_batch_merkle_root завершённого серверного views manifest. Это контроль **всех строк**, а не только числа вариантов. Значения GT/FT/DP/AD/GQ входят в исходные векторы и не изменяются.

Выходные gzip-члены имеют уровень сжатия 1 и mtime=0. Их сжатые байты, размер и SHA могут отличаться от серверного master. PASS подтверждает равенство канонических TSV UTF-8/LF векторов, заголовка, порядка и значений; он не означает побайтовую копию серверного `.gz` и не завершает исходную загрузку автоматически.

Рабочих процессов по умолчанию `max(1,min(6,cpu_count-4))`, максимум 6. Текущая порция ограничена 64 MiB, очередь — 384 MiB и числом рабочих процессов; строки передаются без накопления всех записей. Целевой расход памяти — менее 8 GiB, это конструктивный предел объёма работы, а не заявленный системный Windows Job Object лимит. Предел выполнения — до 8 часов. Сохраняется резерв 15 GiB; сборка требует место для проверенных gzip-блоков и отдельного итогового файла.

Каждый собственный завершённый блок имеет durable checkpoint с source identity, обоими vector proof и SHA **сгенерированного** gzip-блока. При повторе тот же источник и код обязательны; собственные gzip-блоки проверяются и переиспользуются. Временные/чужие выходы не заменяются. Незавершённая сборка остаётся для проверки, не дописывается автоматически. После успеха создаётся LOCAL-RECONSTRUCTION-RECEIPT.json со статусом PASS_SEMANTIC_MASTER_RECONSTRUCTION. Исходные файлы и checkpoint-блоки не удаляются.

Проверка кандидата включает реальные два Windows ProcessPool worker: 138+13 полей, Unicode/TAB/LF/кавычки, phased/partial/missing GT, scored SpliceAI и явную область вне расчёта. Несовпадение source identity или полного derived Merkle не допускает готовый файл. Реальный ограниченный префикс не заменяет последующую полную проверку всех блоков.
