# Краткая инструкция

Все серверные команды выполняются из корня установленного кода. Данные проекта в примерах находятся в `/srv/marina`. Приватные планы запуска уже должны существовать: они связывают входы, версии источников, код и предел времени.

## Уже запущенный проект

Проверить состояние:

```bash
python3 scripts/monitor_pipeline.py --root /srv/marina --once --human
```

Наблюдать раз в минуту:

```bash
python3 scripts/monitor_pipeline.py --root /srv/marina --watch --interval 60 --human
```

Без `--human` выводится прежний JSON. Монитор читает небольшие квитанции и PID, не открывает BAM/VCF и не пересчитывает их SHA. Старая остановленная последовательная очередь показывается как историческая запись, если основной параллельный процесс уже работает. Завершение отмечается по квитанциям, без повторного аудита файлов.

`NOT_CREATED_OR_WAITING` означает, что итоговой квитанции ещё нет. Это не подтверждает запуск следующего контроллера. После готовности откройте `/srv/marina/outputs/cohort-sample-views-v1/index.html` или его сохранённую локальную копию.

## Скачать или проверить базы

Основной подготовщик: [scripts/prepare_all_resources.py](../scripts/prepare_all_resources.py). Проверить состояние и запустить недостающую подготовку на сервере:

```bash
python3 scripts/prepare_all_resources.py --root /srv/marina --status
python3 scripts/prepare_all_resources.py --root /srv/marina --execute
```

Он переиспользует готовые основные ресурсы и работающий загрузчик. Это подготовка основного набора VEP и локальных дополнений, а не установка всех 69 источников из реестра. Фактическая доступность сохраняется в манифестах. В текущем запуске VEP 115/cache 115 уже подготовлен.

Отдельная загрузка архива RefSeq: [scripts/queue_refseq_source_download.py](../scripts/queue_refseq_source_download.py).

```bash
# Только если отдельная очередь RefSeq ещё не запущена:
python3 scripts/queue_refseq_source_download.py
```

Если эта очередь уже работает, второй экземпляр не нужен. Скрипт запускается сразу, без флага `--execute`. Он загружает и проверяет около 25 GB исходного архива; распаковка, установка RefSeq и подключение к аннотации этим не выполняются. Исходный предел времени сохраняется.

## Рабочая схема после VEP

Один общий VCF служит источником итоговых таблиц. Полные исходные поля и генотипы сохраняются; отсутствующие значения не заменяются нулями. Подготовленные правила запуска содержат конкретные входы, версии, код, число процессов и исходный предел бюджета.

| Этап | Исполнитель | Результат в `outputs/` |
|---|---|---|
| 1. Готовый VEP-компонент | завершённый проход `parallel_annotation.py` | `annotated.vcf.gz` и `.tbi`; таблицы старого этапа 06 могут ещё не быть готовы |
| 2. Полные строки и дополнительные источники, параллельно | `direct_fully_annotated_vcf_v3.py` (продолжение v2) | `direct-core-context-v1/cohort.core-context.vcf.gz`, статус `INTERMEDIATE_CORE33_PASS` |
| 3. SpliceAI, одновременно с этапом 2 | `continue_spliceai_reference_context.py` → `run_spliceai_reference_context.py` | `spliceai-reference-context-v1/` |
| 4. Присоединить SpliceAI к VCF | `continue_spliceai_allele_overlay.py` → `apply_spliceai_allele_overlay.py` | `fully-annotated-vcf-v1/cohort.fully-annotated.vcf.gz` и `.tbi` |
| 5. Таблицы из итогового VCF | `continue_packet_views_fast_v2_3.py` → `export_packet_views_fast_v2_1.py` | `cohort-sample-views-v1/` |
| 6. Локальная копия | `sync_completed_small_results_v2.py` — готовые VCF и отчёты; отдельный профиль BAM | выбранная папка на компьютере |

При защитной остановке v2 из-за размера порции версия v3 продолжает с проверенных готовых блоков. Она сверяет исходные записи с готовым VEP, проверяет завершённые блоки и сохраняет их без изменения; только недостающие порции делит на меньшие, оставляя аллель и все образцы вместе. Для этого нужны отдельное проверенное правило продолжения и новая папка состояния; обычное правило v2 для команды v3 не подходит. Старые результаты не удаляются.

Этап 2 переиспользует готовый VEP и согласованный снимок SQLite; VEP и AlphaMissense заново не рассчитываются. Полные строки распределяются по сбалансированным порциям, аллель со всеми образцами остаётся целиком. Проверяются число и порядок строк, все исходные поля, генотипы и контрольные суммы последовательностей строк. Файлы прежнего запуска сохраняются.

Этап 4 ожидает одновременно завершённых этапов 2 и 3. Он добавляет фактические оценки SpliceAI как аллельные поля INFO, сохраняя исходные пакеты строк. Этап 5 получает дополнительные столбцы SpliceAI из INFO **этого же VCF** при единственном чтении пакетов; внешняя TSV с предсказаниями для этого не нужна.

Исторические контроллеры `continue_combined_annotation_master.py`, `continue_fully_annotated_vcf.py` и `continue_cohort_sample_views_v3.py` относятся к схеме с промежуточными полными таблицами. Их не запускают одновременно с новой схемой. Новая схема не создаёт фиктивные квитанции завершения старых 06/07.

## Запуск подготовленных этапов

Если процесс уже работает, повторный запуск не нужен. Команды ниже выполняются на сервере из корня проверенной копии кода. Переменные указывают на **существующие проверенные приватные правила**, а не на файлы-примеры. Пути к образцам и значения подключения в GitHub не публикуются.

Параллельное формирование строк и дополнительных аннотаций:

```bash
python3 "$CORE33_ENTRY" run --rule "$CORE33_RULE" --reviewed-rule-sha256 "$CORE33_RULE_SHA256" --execute
```

SpliceAI запускается отдельно в указанной правилом существующей среде с TensorFlow:

```bash
"$SPLICEAI_PYTHON" "$SPLICEAI_ENTRY" run --rule "$SPLICEAI_RULE" --reviewed-rule-sha256 "$SPLICEAI_RULE_SHA256" --execute
```

Контроллер присоединения оценок ожидает готовности обоих входов:

```bash
"$ANNOTATION_PYTHON" "$OVERLAY_ENTRY" run --rule "$OVERLAY_RULE" --reviewed-rule-sha256 "$OVERLAY_RULE_SHA256" --execute
```

Исправление загрузки модуля для параллельных таблиц описано в [инструкции продолжения v2.2](fastviews-loader-recovery-v2-2.md). Новый контроллер регистрирует динамический модуль перед передачей функций рабочим процессам; экспортёр и правила отбора вариантов сохраняются.

Контроллер итоговых таблиц ожидает готового VCF:

```bash
"$ANNOTATION_PYTHON" "$FAST_VIEWS_ENTRY" --rule "$FAST_VIEWS_RULE" --rule-sha256 "$FAST_VIEWS_RULE_SHA256" --execute --watch
```

`CORE33_ENTRY` — проверенная копия `direct_fully_annotated_vcf_v3.py` (продолжение v2); `SPLICEAI_ENTRY` — `continue_spliceai_reference_context.py`; `OVERLAY_ENTRY` — `continue_spliceai_allele_overlay.py`; `FAST_VIEWS_ENTRY` — `continue_packet_views_fast_v2_3.py`. Без `--execute` команды показывают план или состояние. Режим наблюдения не равен завершению анализа. Запуски ограничены исходным сроком бюджета; этот срок сам по себе не отключает оплату VM.

## Файлы готовой выдачи

Пути ниже указаны относительно `cohort-sample-views-v1/`. Имена файлов образцов перечислены в `manifest.json`, поле `sample_file_labels`.

| Что нужно | Файл |
|---|---|
| Основной общий VCF со встроенными дополнительными данными | `vcf/cohort.fully-annotated.vcf.gz` и `.tbi` |
| Открыть таблицы и наборы | `index.html` |
| Полная таблица из VCF, все транскрипты | `masters/cohort.master.tsv.gz` |
| Общий топ-20 | `tables/cohort.top20.tsv` |
| Общая таблица последствий | `tables/cohort.functional.tsv.gz` |
| Категории и пути к отдельным файлам | `tables/functional-category-index.tsv` |
| Полная таблица образца | `masters/<метка>.master.tsv.gz` |
| Топ-20 образца | `tables/<метка>.top20.tsv` |
| Последствия образца | `tables/<метка>.functional.tsv.gz` |
| VCF образца с пакетом только этого образца | `vcf/sample_0001.annotated.vcf.gz` … `sample_0004.annotated.vcf.gz`, с индексами |
| Фактические источники и контрольные суммы | `manifest.json` |

Недоступные оценки и источники отмечаются явно. Отсутствующий генотип не считается референсным. Категории считаются по уникальным аллелям с учётом транскриптных последствий; их суммы могут превышать число вариантов. MT остаётся отдельным приложением; MT-варианты не добавляются в ядерный VCF.

## Что находится внутри VCF

`INFO/WGS_EVIDENCE` содержит полные строки исходной аннотации и применённый дополнительный контекст. Схема и контрольные суммы порций — в `WGS_EVIDENCE_SCHEMA`. Кодек: JSON UTF-8 → zlib → base64url без дополнения. `WGS_GENE`, `WGS_CONSEQUENCE`, `WGS_CLINVAR`, `WGS_GNOMAD_*` и другие поля дают читаемые сводки. Полные применённые публичные материалы также включены в файл; ссылки на внешние пути не заменяют сами доказательства.

SpliceAI находится в `SpliceAI`, `WGS_SPLICEAI_STATUS`, `WGS_SPLICEAI_EVIDENCE`; отдельный заголовок `WGS_SPLICEAI_SCHEMA` описывает проекцию `ALLELE_INFO_V1_ROW_PROJECTION_ON_READ`. Это четыре DS и четыре DP, модель, её версия и область расчёта. Полная master-таблица получается этапом 5 из пакетов строк **и** этих аллельных полей INFO.

В этой конфигурации область SpliceAI — согласованная панель из 39 генов. Прогноз относится к модели GENCODE24 gene union, без переобозначения как конкретного VEP ENST-транскрипта. Вне области расчёта, при несовпадении модели или неподдерживаемом аллеле сохраняется отдельный статус. Отсутствующая оценка не равна нулю.

Старый `embed_vcf_evidence.py decode` восстанавливает физически сохранённые строки пакета, но не добавляет новую проекцию SpliceAI. Для полного master с этими столбцами используйте новый экспорт этапа 5. Пообразцовые VCF содержат только строки и генотип соответствующего образца; общая матрица остальных образцов из пакетов удаляется.

## Сохранить готовый VEP VCF раньше итогового результата

Это отдельный файл, например `VCF/cohort.vep115.annotated.vcf.gz` и его `.tbi`. Он не заменяет последующий файл со всеми фактически применёнными источниками и SpliceAI. Завершённый VEP-компонент можно сохранить, даже если старое формирование таблиц 06 ещё работает; его происхождение фиксируется отдельной квитанцией, без объявления всего этапа 06 завершённым.

В PowerShell, с Python существующей среды Native SFTP:

```powershell
python transfer/download_completed_component.py --plan "$env:VEP_COMPONENT_PLAN"
python transfer/download_completed_component.py --plan "$env:VEP_COMPONENT_PLAN" --auth-config "$env:NATIVE_SFTP_CONFIG" --execute
```

Первая команда — проверка состава без авторизации и сети. Вторая использует проверенный приватный план, существующее подключение и SSH host key. Скачивание продолжается из `.part`, не заменяет отличающийся готовый файл и сохраняет 15 GiB свободного места. Проверка локальной копии — по размеру и неизменности источника; новый SHA содержимого не вычисляется. Фактический статус находится в `state_directory/status.json` указанного плана.

## Сохранить таблицы и отчёты на компьютер

В PowerShell из корня кода, используя Python существующей среды Native SFTP и подготовленный приватный профиль:

```powershell
python transfer/sync_completed_small_results_v2.py --profile "$env:SMALL_RESULTS_PROFILE" --execute --watch
```

`SMALL_RESULTS_PROFILE` — путь к подготовленному приватному профилю. Уже работающую синхронизацию повторно не запускают. Значения подключения и ключи в команду не вставляются. Без `--execute --watch` команда показывает состав выбранных файлов без чтения ключа и без сети.

Версия v2 ожидает завершения итогового `cohort-sample-views-v1`, без ожидания четырёх заменённых промежуточных этапов. Подготовленный план также включает отдельный завершённый MT-контекст. Команда скачивает VCF, таблицы, отчёты и квитанции и добавляет их в локальную выдачу. Для ещё не завершённых этапов показывает ожидание. Работающая загрузка BAM остаётся отдельной; BAM/BAI, gVCF и базы эта команда не переносит. Используются собственные папка загрузок, блокировка и `.part` для продолжения.

Проверка — размер и неизменность источника, без нового SHA-256 содержимого. Статус `COMPLETED_SIZE_ONLY` не является SHA-проверкой. Откройте локальный `INDEX.html`; полная выбранная выдача готова после завершения всех требуемых этапов и их переноса. [Профиль и статусы синхронизации](small-result-sync-v2.md).

Для просмотра или обновления списка завершённых серверных файлов используется [transfer/prepare_native_plan.py](../transfer/prepare_native_plan.py). План метаданных отличается от конфигурации SFTP и сам ничего не скачивает. [Однократный просмотр плана](native-plan-completed-sidecars-v2.md). Отдельные загрузки по уже существующему профилю выполняет `native_sftp_download.py`; второй экземпляр работающего загрузчика не запускают.

## Новый сервер

Начните с [установки](server-setup.md), [референса](reference-setup.md) и [подготовки источников](resource-bootstrap.md). Для нового анализа из BAM используются этапы `workflow.py call`, `joint`, `filter`, `annotate`, `report`; это отдельная подготовка, не команда возобновления текущего процесса. Завершённые этапы переиспользуются только при совпадении входов, кода и параметров. Предел времени скриптов не останавливает оплату облачной VM.
