# Семь этапов анализа

Команды выполняются в корне кода на Linux-сервере. Реальные данные, настройки и результаты находятся в `/srv/marina`, вне GitHub. По умолчанию Python-команда показывает план; `--execute` разрешает расчёт. Этапы 3–5 не требуют баз аннотации и могут работать одновременно с их загрузкой. Сначала проверьте, не запущена ли уже нужная очередь: повторный параллельный запуск не ускоряет обработку.

| Этап | Что делает | Результат |
|---|---|---|
| 1. Подготовка | Установка инструментов, фиксированного референса и баз, проверка версий/контрольных сумм | Инструменты и проверенные ресурсы на сервере |
| 2. Выравнивание | FASTQ → выравнивание на полный референс → сортировка → дубликаты → QC | BAM, BAI, метрики каждого образца |
| 3. Поиск вариантов | HaplotypeCaller использует готовые BAM в явно заданных интервалах и с заданной плоидностью | Отдельный gVCF каждого образца |
| 4. Совместное генотипирование | GATK GenomicsDBImport + GenotypeGVCFs, нормализация | Общий нефильтрованный `cohort.raw.vcf.gz` |
| 5. Фильтрация | Разные пороги SNV/indel, флаги качества сайта и каждого генотипа, сохранение исходных записей | VCF со всеми флагами и отдельная качественная выборка |
| 6. Аннотация | Офлайн VEP, ClinVar, ClinGen и доступные дополнительные источники, учёт отсутствующих источников | Аннотированный VCF и полные таблицы доказательств |
| 7. Отчёт | Полные приложения, основные кандидаты, топ-10/20, пересечения, счётчики последствий и ручной лист ACMG | HTML, TSV/TSV.gz и описание методов/ограничений |

Выгрузка завершённых результатов на компьютер работает отдельно от этапов расчёта. Она не скачивает большие базы, референс, FASTQ или незавершённые файлы. В локальном `INDEX.html` видны только проверенные результаты; сохранение отдельного файла не означает завершение всей резервной копии.

## После четырёх готовых BAM

Создать приватный план, пока базы ещё скачиваются:

```bash
python3 scripts/configure_workflow.py \
  --root /srv/marina \
  --resource-manifest /srv/marina/resources/annotation/vep115.2-cache115-clinvar20261025-clingen20261105-publicextras-v2/resource-manifest.json \
  --allow-pending-resources --execute
```

Эта команда только проверяет существующие BAM и создаёт настройки. Не повторяет выравнивание. Затем запуск по этапам:

```bash
python3 scripts/workflow.py 3 --execute
python3 scripts/workflow.py 4 --execute
python3 scripts/workflow.py 5 --execute
```

Запускать следующую команду после успешного завершения предыдущей. Каждый этап проверяет контрольные суммы входов и квитанции предыдущего этапа. Завершённые контрольные точки используются повторно при неизменных входах, коде и настройках. При изменении политики следует создавать новый план с другим `--label`, сохраняя прежние результаты.

После готовности баз:

```bash
python3 scripts/workflow.py 6 --execute
python3 scripts/workflow.py 7 --execute
```

Для полного продолжения с этапа 3 до 7 одной командой, когда базы уже готовы:

```bash
python3 scripts/workflow.py all --execute
```

`all` продолжает этапы 3–7; оно не создаёт сервер, не загружает исходные данные и не повторяет этап выравнивания. Состояние:

```bash
python3 scripts/workflow.py status
```

## Границы текущего плана

По умолчанию поиск SNV/малых indel выполняется на **chr1–chr22, диплоидно**, по четырём готовым BAM. Наличие BAM на полном референсе не означает готовность вариантов по всем хромосомам. chrX/chrY требуют отдельной явной политики интервалов и плоидности для каждого образца; chrM, CNV/SV и повторы требуют отдельных методов. Дополнительные callset задаются через `--callsets-manifest`, а не угадываются по имени образца.

Технический пилот содержит полно-референсное выравнивание первого образца, но его gVCF относится только к chr1. Этот пилотный gVCF не подставляется вместо полного нового callset.

Покрытие исходных данных неоднородно. Отсутствие варианта в VCF не доказывает качественно прочитанный референсный генотип. Флаги качества, функциональные последствия и клиническая классификация — разные поля. stop-gain, stop-loss, start-loss, frameshift и splice считаются отдельно, без повторного счёта одной аллели из-за нескольких транскриптов. Топ-10/20 — очереди ручного рассмотрения; диагноз и ACMG-класс автоматически не присваиваются.

## Где лежат новые результаты

```text
/srv/marina/outputs/workflow-v1/
  checkpoints/03_call/gvcf/<callset>/<sample>/  # gVCF и индексы
  checkpoints/04_joint/                      # совместное генотипирование
  stages/03_call/                            # список gVCF и область анализа
  stages/04_joint/                           # общий исходный VCF
  stages/05_filter/                          # VCF с флагами и QC
  stages/06_annotate/                        # полные аннотации
  stages/07_report/                          # отчёт и таблицы
```

Результат считается завершённым после `workflow-receipt.json` со статусом PASS и проверяемыми SHA-256. Частичные директории остаются для диагностики и не выдаются за готовые. Лимит времени скрипта не прекращает оплату VM: завершать аренду следует отдельно после проверки локальных копий.
