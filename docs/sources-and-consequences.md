# Источники и последствия вариантов: Analysis 2

Список Analysis 1 предоставлен пользователем как история предыдущего анализа. Он не означает, что старые базы, версии или результаты используются в новом анализе. Analysis 2 начинается с нового анализа FASTQ; сравнение со старыми VCF не входит в задачу.

## Что означает тип и последствие варианта

VEP вычисляет последствия относительно конкретного транскрипта по референсу GRCh38 и аннотации Ensembl. Это не поиск готового диагноза в ClinVar. Один аллель может иметь разные последствия в разных транскриптах; полная таблица сохраняет их все.

| Что нужно увидеть | Поле или термин в нашем конвейере |
|---|---|
| Замена одного нуклеотида | `variant_type=SNV`; SNP обычно обозначает популяционный полиморфизм, поэтому не используем это слово для любой замены |
| Вставка / делеция | `variant_type=insertion` / `deletion`; точное последствие сохраняется отдельно |
| Замена аминокислоты | `consequence=missense_variant`, `missense=1` |
| Синонимическая замена | `synonymous_variant`, `synonymous=1` |
| Преждевременный стоп | `stop_gained`, `stop_gain=1` |
| Потеря стоп-кодона | `stop_lost`, `stop_loss=1` |
| Потеря старт-кодона | `start_lost`, `start_lost=1` |
| Сдвиг рамки считывания | `frameshift_variant`, `frameshift=1` |
| Вставка / делеция без сдвига рамки | `inframe_insertion` / `inframe_deletion` в `consequence` |
| Сайт или область сплайсинга | `splice_donor_variant`, `splice_acceptor_variant`, другие `splice_*`; поле `splice` |
| Интрон, UTR, межгенная область и остальные эффекты | Полное поле `consequence` и исходные VEP-поля в `vep_all_csq_json` |
| Кандидат на потерю функции | `plof_candidate=1` для stop-gain, frameshift и канонического donor/acceptor; это предварительный флаг |

Ген, идентификаторы, транскрипт с версией, экзон/интрон, HGVS c./p., положение в белке и VEP IMPACT сохраняются рядом. Подсчёты `consequence_counts.json` используют уникальные нормализованные аллели на уровнях raw/QC/candidate, отдельно по образцам и когорте. Пересекающиеся флаги не складываются как независимые варианты. Top10/Top20 — отдельные очереди для просмотра, а не названия последствий.

LoF и GoF — механизмы изменения функции, а не универсальные автоматические метки VEP. `plof_candidate` не доказывает LoF, NMD, PVS1 или патогенность. Stop-loss не доказывает GoF. Для вывода нужны конкретные ген, заболевание, транскрипт и доказательства; поля `mechanism_status` и `nmd_assessment` остаются неоценёнными до такой проверки. LOFTEE пока не установлен; его меток HC/LC нет.

## Как включён список источников пользователя

Состояние на 05.11.2026; полный реестр требований: [evidence-sources.example.json](../config/evidence-sources.example.json). Наличие строки в реестре не означает установленную базу или применение к пациентам.

| Группа | Использование в Analysis 2 |
|---|---|
| VEP 115 / Ensembl / GRCh38 | Аннотатор установлен, кэш ещё загружается; пациентская аннотация не завершена |
| ClinVar, ClinGen validity/dosage, HGNC, HPO, MANE | Локальные серверные файлы подготовлены; применять после прохождения общей проверки ресурсов |
| gnomAD Exomes/Genomes, rs/dbSNP, SIFT, PolyPhen | Запрошены поля локального VEP-кэша; фактические версии и доступность берутся из проверенного `info.txt`, не предполагаются заранее |
| RefSeq / MANE Select / MANE Plus Clinical | MANE-сводка подготовлена; это не означает загрузку полного RefSeq или RefSeq/merged VEP-кэша |
| AlphaMissense | Обе таблицы canonical/isoforms подготовлены; точное сопоставление аллеля, транскрипта и белковой замены обязательно |
| ClinGen VCEP / gene-specific ACMG | Проверка актуальных правил для конкретной пары ген–заболевание; не универсальный автоматический ACMG-классификатор |
| OMIM, GeneReviews, Orphanet, LOVD, PubMed | Источники контекста и литературных доказательств; полного локального импорта не заявляем. PMID из VEP — не выполненный систематический обзор литературы |
| dbNSFP | Указан как ручной/авторизованный дополнительный источник; 4.9a из Analysis 1 не переносится автоматически, новый пакет не установлен |
| VarSome | Вторичный агрегатор для проверки специалистом; не независимое доказательство и не автоматическая отправка пациентских вариантов |
| FATHMM, CADD, REVEL, SpliceAI | Дополнительные вычислительные оценки, пока не подключены; отсутствующая оценка не означает доброкачественность |

Установка и фактическая готовность: [databases.md](databases.md). Поля, ранжирование, локальные адаптеры и ручной ACMG: [annotation-report.md](annotation-report.md). Пациентские варианты не передаются во внешние сервисы.

Официальная схема последствий: [Ensembl calculated consequences](https://www.ensembl.org/info/genome/variation/prediction/predicted_data.html).
