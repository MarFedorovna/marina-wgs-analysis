# Аннотация геномных вариантов

Готовый VEP VCF → параллельное добавление подготовленных источников → SpliceAI внутри того же VCF → общий топ-20 и функциональные категории → VCF и таблицы четырёх образцов → локальная копия.

Текущая выдача готова: итоговый VCF (8 461 702 199 байт) и индекс уже сохранены локально; серверный набор таблиц и четырёх пообразцовых VCF завершён с PASS. Перенос остальных файлов выдачи выполняется отдельно и ещё не означает, что весь набор находится на компьютере. Дополнительные X/Y calling и серверная аннотация также завершены; локально уже сохранён calling, перенос аннотированного X/Y набора подтверждается отдельно.

## Где запускать

Серверные команды — в **Terminal JupyterLab** или по SSH на Ubuntu, из папки этого репозитория. В JupyterLab: `File → New → Terminal`, затем `cd` в папку кода. Команды локального сохранения выполняются в PowerShell на компьютере.

## Посмотреть состояние

Из корня кода на сервере:

```bash
python3 scripts/monitor_pipeline.py --root /srv/marina --once --human
```

Для обновления раз в минуту добавьте `--watch --interval 60` вместо `--once`. Монитор ничего не запускает и не останавливает. Если аннотация уже работает, повторный запуск не нужен.

## Подготовить новый сервер и референс

На новом сервере сначала установите код и подготовьте приватные `samples.tsv`, пути FASTQ и исходные контрольные суммы. Они хранятся в `/srv/marina/private/`. Текущий работающий анализ уже прошёл подготовку.

| Действие | Команда на сервере | Что получится |
|---|---|---|
| Docker, GPU runtime и основные инструменты | `sudo bash scripts/bootstrap-server.sh /srv/marina` | установленное окружение |
| BWA для проверки индексов | `sudo apt-get install -y --no-install-recommends bwa` | host BWA 0.7.17 |
| Скачать GRCh38 и готовые индексы | `python3 scripts/prepare_reference.py --lock config/broad-hg38-v0.sources.lock.json --root /srv/marina/references --execute` | FASTA, FAI, dictionary, ALT и BWA-индексы с квитанцией |
| Проверить окружение | `sudo bash scripts/preflight-server.sh /srv/marina` | проверка GPU, RAM, диска и Docker |
| Подготовить основные базы | `python3 scripts/prepare_all_resources.py --root /srv/marina --execute` | VEP cache и основные локальные источники |
| Инструменты отчёта | `bash scripts/setup_report_env.sh` | отдельное окружение для Word и графиков |

На новом сервере подготовщику баз также передают `--created-utc` с **фактическим временем создания VM**; на текущем оно уже записано в приватном бюджете. Полный реестр включает дополнительные источники с отдельными способами доступа — команда основных баз не означает установку каждого из них.

Есть [единый установочный скрипт `setup_project.sh`](scripts/setup_project.sh): он устанавливает окружение, скачивает референс и создаёт приватный план пилота при наличии TSV образцов и манифеста исходных файлов. [Команды и обязательные входы](docs/server-setup.md), [подробности референса](docs/reference-setup.md), [скачивание баз и RefSeq](docs/QUICKSTART.md#скачать-или-проверить-базы).

После четырёх готовых BAM этапы `workflow.py call`, `joint`, `filter` дают gVCF, совместный VCF и фильтрацию. [Настройка и команды](docs/stages.md). Завершённый проход VEP переиспользуется; дальнейшая схема ниже не требует повторного VEP или повторной записи промежуточных полных CSV.

Этапы ожидают завершения своих входов. Наличие скрипта или запущенного ожидания ещё не означает готовность результата. Команды запуска и входы каждого шага: [краткая инструкция](docs/QUICKSTART.md).

## Локальное сохранение

[Загрузчик завершённого набора](docs/cohort-views-dataset-download.md) использует 16 закреплённых SFTP-подключений и возобновляемые блоки в заранее выделенных `.part`. Уже сохранённые общий VCF и индекс переиспользуются жёсткими ссылками без второй копии. Размер предварительно выделенного файла не показывает прогресс: учитываются только подтверждённые блоки. Сначала в очередь поступают top-20 и небольшие отчёты. Базы, BAM и gVCF в этот перенос не входят.

## Локальная стартовая страница и восстановление

Откройте `START.html` в выбранной папке результатов. [Генератор](transfer/write_results_home.py) создаёт её только из метаданных: ссылки на общий VCF, четыре BAM, top-20, все функциональные категории, X/Y и MT. Прежний подробный `INDEX.html` сохраняется. Показатель переноса берётся из подтверждённых блоков, не из полного размера `.part`.

Для уже полностью выделенного набора есть отдельное [resume-only продолжение](docs/cohort-dataset-preallocated-resume-v2.md). Оно проверяет физическую аллокацию всех файлов до авторизации и не создаёт новые `.part`.

[Локальное восстановление master из VCF](docs/local-master-recovery.md) подготовлено как резервный offline-инструмент: сохраняет все поля и порядок строк и проверяет исходные блоки и итоговый Merkle. По умолчанию выполняется только ограниченный preview; полный запуск требует проверки и отдельной папки. Сжатые байты восстановленного `.gz` могут отличаться от серверной копии. Полное восстановление текущей выдачи не запускалось.

## Где открыть результат

Основной итоговый файл — `/srv/marina/outputs/fully-annotated-vcf-v1/cohort.fully-annotated.vcf.gz` с индексом `.tbi`. Дополнительная аннотация хранится внутри VCF. Главная страница таблиц и пообразцовых наборов:

```text
/srv/marina/outputs/cohort-sample-views-v1/index.html
```

Таблицы строятся из итогового VCF: полный master, общий топ-20, общие аллели и их встречаемость, функциональные категории, отдельный SpliceAI top-20. Для каждого образца выдаются свой VCF, master, топ-20 и категории. Пакет пообразцового VCF содержит строки только этого образца. Полные транскриптные строки сохраняются; категории могут пересекаться, топ-20 не дополняется искусственно.

SpliceAI хранит четыре delta score, четыре позиции и источник модели внутри VCF. Область расчёта ограничена согласованной панелью из 39 генов; неподдерживаемые варианты и область вне расчёта имеют явный статус, а не нулевую оценку. Оценки относятся к модели гена и не выдаются за предсказание конкретного VEP-транскрипта.

Отдельную копию завершённого VEP-компонента с индексом можно сохранить до окончания дополнительной аннотации: [инструкция](docs/QUICKSTART.md#сохранить-готовый-vep-vcf-раньше-итогового-результата). Такой файл не обозначается как итог всех источников.

Основная завершённая область — SNV и малые indel на chr1–chr22. Дополнительный [X/Y germline calling](docs/xy-germline-executor-v1.md) и [его серверная аннотация](docs/supplementary-annotation.md) завершены отдельно; calling уже сохранён локально, аннотированная выдача требует собственной квитанции переноса. Использована явно разрешённая модель плоидности из QC и диплоидные PAR на X после проверки исходного маскирования Y-PAR, без назначения клинического кариотипа. Старый аутосомный VCF не перезаписывается. [Техническая X/Y-проверка](docs/xy-target-quantitative-qc-v2.md), calling, аннотация и локальная копия имеют разные статусы.

Функциональные таблицы охватывают все аннотированные последствия, а не только top-20 или stop-gained/stop-lost. Каждая категория имеет семь областей выдачи: весь набор, четыре индивидуальных набора, одинаковые аллели минимум у двух образцов (`shared_ge2`) и одинаковые аллели у всех четырёх (`all4`). Состояния raw/QC/candidate различаются; совпадение гена не считается совпадением варианта. Полный список и пути находятся в `tables/functional-category-index.tsv`.

[Дополнительная аннотация X/Y](docs/supplementary-annotation.md) использует настоящий PASS calling, запускает офлайн-аннотацию, встраивает все фактические строки доказательств в дополнительный VCF и строит функциональные таблицы из его сохранённого содержимого. Для индивидуальных VCF пакет очищается от строк других образцов; manifest/receipt отражают итоговые файлы после очистки.

MT имеет отдельную завершённую [аннотацию последствий](docs/mt-consequence-annotation.md): исходные Mutect2 INFO/FORMAT, GT, AF/HL и фильтры сохраняются, последствия рассчитываются с митохондриальным генетическим кодом. Полные аннотированные MT VCF и таблицы уже сохранены локально. [Экспорт MT-категорий](docs/mt-functional-tables.md) также завершён на сервере; его локальный перенос подтверждается отдельно. Этот набор имеет свою квитанцию: семь областей выдачи и два независимых уровня присутствия — исходная запись вызова и буквальный site `FILTER=PASS`. Отсутствие записи не объявляется референсным генотипом; ядерные правила GQ/плоидности к MT не применяются. Старый частотный MT-контекст, новые последствия и новые категории — разные выдачи.

Текущий топ-20 — общий исследовательский рейтинг, а не завершённая HCM-приоритизация или диагноз: у первых пяти строк флаги `phenotype_context_rank` и `target_gene_context_rank` равны 0. Ранжирование не изменялось; ACMG требует отдельной проверки доказательств.
