# Marina WGS: воспроизводимый исследовательский пайплайн

Репозиторий содержит скрипты и документацию. Пациентские FASTQ/BAM/VCF, таблицы, отчёты, кэши баз, токены и тестовые файлы сюда не входят и не должны добавляться.

## Что делает пайплайн

Пайплайн рассчитан на четыре образца WGS человека (GRCh38) и разделён на независимые этапы. Каждый этап принимает явно заданные входы и пишет результат в отдельный каталог. Пути к данным и секреты задаются только в приватном конфигурационном файле или переменными окружения.

## Этапы от входа до отчёта

### 0. Контроль входов и воспроизводимость

1. Создать приватный `samples.tsv`: `sample_id`, `fastq_r1`, `fastq_r2`, ожидаемые контрольные суммы.
2. Проверить контрольные суммы, место на диске, версии инструментов, референс и доступ к базам.
3. Не помещать `samples.tsv`, FASTQ/BAM/VCF, токены и локальные конфиги в Git.

Основные скрипты: `configure_workflow.py`, `configure_pilot.py`, `preflight-server.sh`, `resource_status_snapshot.py`, `monitor_pipeline.py`.

### 1. Референс GRCh38

Скачать FASTA GRCh38 и проверить `FAI`, sequence dictionary, ALT/decoy и индексы BWA-MEM2. Для всех образцов используется один зафиксированный референс и его SHA-256.

Основные скрипты: `prepare_reference.py`, `reference_access_snapshot.py`, `probe_grch38_xy_reference.py`.

### 2. Выравнивание и BAM/QC

В выполненном анализе FASTQ выравнивались на GPU с помощью NVIDIA Parabricks; BWA-MEM2 предусмотрен как CPU-альтернатива. Затем выполняются сортировка, маркировка дубликатов, индексация BAM и базовая статистика покрытия/дубликатов. Результаты этого этапа не публикуются в репозитории.

Основные скрипты: `run_parabricks.py`, `workflow.py`, `calling_stages.py`, `gene_coverage.py`, `joint_scatter.py`.

### 3. Герминальный вызов вариантов

Для каждого образца gVCF строится с помощью Parabricks HaplotypeCaller; затем выполняются совместная генотипизация с GATK, нормализация REF/ALT и индексация. Для SNP/indel применяется один и тот же GRCh38 reference dictionary.

Основные скрипты: `calling_stages.py`, `workflow.py`, `parallel_annotation.py`.

### 4. Фильтрация качества

Сначала сохраняются исходные значения, затем формируется исследовательский PASS-набор. Использованные пороги:

- генотип: `DP >= 10`, `GQ >= 20`;
- сайт: `QUAL >= 30`;
- SNP: `QD >= 2`, `FS <= 60`, `SOR <= 3`, `MQ >= 40`, `MQRankSum >= -12.5`, `ReadPosRankSum >= -8`;
- indel: `QD >= 2`, `FS <= 200`, `ReadPosRankSum >= -20`;
- отсутствующие QC-аннотации не проходят молча: они помечаются для ручной проверки.

Это исследовательский фильтр, а не автоматическая клиническая классификация.

### 5. Первичная аннотация

Основной слой — Ensembl VEP для GRCh38 с зафиксированным cache. В VCF/master сохраняются исходный вариант, транскрипт, HGVS, CONSEQUENCE, ген, аллельные частоты и идентификаторы источников. Неизвестные или отсутствующие значения не заменяются догадками.

Основные скрипты: `annotation_stages.py`, `parallel_annotation.py`, `continue_fully_annotated_vcf.py`, `prepare_annotation_resources.py`, `prepare_all_resources.py`.

### 6. Источники аннотации и их назначение

- **ClinVar** — опубликованные клинические утверждения и уровень согласия; используется как evidence, не как безусловный диагноз.
- **gnomAD exomes/genomes** — популяционные AF/AC/AN и контроль редкости.
- **dbSNP** — идентификаторы вариантов.
- **dbNSFP** — агрегированные функциональные предикторы, когда доступен соответствующий public snapshot.
- **HGNC** — стабильные символы и идентификаторы генов.
- **MANE Select/Plus Clinical и RefSeq** — клинически согласованные транскрипты.
- **HPO** — связь признаков с генами; конкретный фенотип задаётся отдельно и не предполагается по умолчанию.
- **ClinGen Gene–Disease Validity, Dosage и VCEP** — сила gene–disease связи и gene-specific правила; слабые/спорные связи не получают положительный boost.
- **Orphanet, PubMed** — контекст заболевания и литература для ручной проверки.
- **UniProt, GTEx/pext** — белковый и тканевой контекст, не самостоятельное доказательство патогенности.
- **AlphaMissense, SIFT, PolyPhen, CADD, REVEL, FATHMM** — вычислительные предикторы; их баллы показываются отдельно и не заменяют ACMG evidence.
- **SpliceAI** — отдельный слой splice-предсказаний; версия, модель и статус должны быть записаны в manifest.
- **MITOMAP/gnomAD-MT/HelixMTdb** — только для mtDNA и только в MT-ветке.

Полные базы HGMD, OMIM, GeneReviews, LOVD и VarSome не импортируются автоматически без соответствующего доступа. Модуль OMIM в OpenCRAVAT может возвращать идентификаторы генов без импорта полной базы. Если источник недоступен, это явно указывается в manifest.

### 7. Отбор и приоритизация для ССЗ

Рассматривается полный аутосомный набор, прошедший технический QC. Для носителя нужны альтернативный генотип, FT=PASS, DP >= 10 и GQ >= 20. Кандидат включается при чёткой классификации ClinVar Pathogenic/Likely pathogenic либо функциональном последствии с максимальной доступной gnomAD AF <= 0,01; функциональные варианты без доступной AF сохраняются с явным статусом.

Функциональные категории объединяют данные доступных транскриптов VEP и OpenCRAVAT. Максимальная AF рассчитывается по доступным исходным данным VEP и общей и популяционным AF gnomAD4 OpenCRAVAT. Высокая AF при включении по ClinVar явно отмечается и снижает приоритет.

Контекст сердечно-сосудистых заболеваний определяется по доступным кураторским связям ClinGen gene–disease с классификациями Definitive, Strong или Moderate и поиском соответствующих терминов в заболевании или экспертной группе. Этот подход не охватывает все возможные гены ССЗ и не устанавливает диагноз.

Рейтинг — исследовательская эвристика: сначала учитываются высокая частота, связь гена с ССЗ, клинические утверждения и противоречия ClinVar, функциональное последствие, наличие и величина AF, затем качество генотипа и наличие оценок. Предикторы показываются с источником и транскриптом; их нельзя считать независимыми доказательствами автоматически. Итоговый класс ACMG автоматически не присваивается.

### 8. Полные списки

Итоговая структура отчёта включает полный ранжированный список прошедших отбор, полные списки по каждому образцу, варианты минимум у двух и у всех образцов, а также отдельные функциональные категории: stop-gained, stop-lost, start-lost, frameshift, splice acceptor/donor/region, missense, synonymous, in-frame и pLoF. Категории могут пересекаться: принадлежность может определяться другим транскриптом, чем показанный в основной строке.

X/Y представлены полным QC-набором и отдельными списками по образцам; MT — отдельными PASS-вызовами и списками по образцам. Для каждой строки сохраняются носители, вариант, транскрипт, показатели качества и доступные аннотации. В таблицах общих вариантов метрики относятся к явно названному образцу.

Итоговый сборщик опубликован: `scripts/prepare_full_cvd_views.py` готовит полные списки, а `scripts/write_full_cvd_xlsx.py` формирует Excel. Команды и необходимые приватные входы описаны ниже.

Основные скрипты: `continue_cohort_sample_views_v3.py`, `export_cohort_sample_views_v3.py`, `export_consequence_tables.py`, `prepare_mt_xy_annotation_inputs.py`, `audit_opencravat_result.py`.

### 9. X/Y и митохондриальная ветки

X/Y обрабатываются с отдельным QC покрытия и генотипов; XX/XY не объявляются клиническим кариотипом без независимого подтверждения. mtDNA анализируется отдельно: собственные правила гетероплазмии/AF, MITOMAP/gnomAD-MT-контекст и функциональные категории. Диплоидные autosomal-пороги нельзя бездумно переносить на MT.

Основные скрипты: `run_xy_germline.py`, `technical_xy_qc.py`, `sex_chromosome_plan.py`, `annotate_mitochondrial_consequences.py`, `audit_mitochondria.py`, `mt_phenotype_context_review.py`.

### 10. Поддержка чтениями и ручная интерпретация

Для выбранных SNV локально проверяются ALT-чтения, MAPQ/BaseQ, число независимых шаблонов и баланс цепей; затем выполняется визуальная проверка в IGV. Это техническая проверка, не замена ACMG/AMP. Финальный ACMG разбор делает исследователь по ClinGen/ACMG evidence codes (например, PVS1, PS, PM, PP, BS, BP) с сохранением ссылки на источник и ручного решения.

Основные скрипты: `review_candidate_snv_reads.py`, `research_review_contracts.py`, `validate_annotation_controls.py`.

## Дополнительная аннотация OpenCRAVAT и проверка

После первичной аннотации подготовленные варианты можно дополнительно обработать в OpenCRAVAT. Подключаемые модули и их версии следует фиксировать для каждого запуска; присутствие модуля не гарантирует наличие оценки для каждого варианта. Пустое значение означает отсутствие доступного результата, а числовой ноль — реально записанный результат. Результаты сопоставляются по сборке, хромосоме, нормализованным REF/ALT и, для зависящих от транскрипта оценок, гену и транскрипту.

`scripts/prepare_mt_xy_annotation_inputs.py` подготавливает имеющиеся в структуре проекта X/Y и MT результаты; это не новый variant calling. Для X/Y использует PASS-сайт и альтернативный генотип с FT=PASS, DP≥10 и GQ≥20; для MT сохраняет показатели исходного вызова и не переносит ядерные пороги автоматически. `scripts/audit_opencravat_result.py` проверяет SQLite-результат, покрытие полей и связи вариантов с образцами. Набор ожидаемых модулей в аудите ориентирован на ядерный запуск: для MT сравнивайте вывод с фактически выбранными модулями, указанными в задании. Недостающие варианты и значения должны оставаться явно отмеченными.

```bash
python3 scripts/prepare_mt_xy_annotation_inputs.py --help
python3 scripts/audit_opencravat_result.py --help
```

## Минимальный запуск

Команды ниже — шаблон. Они требуют приватных путей и настроек; пациентские пути намеренно не указаны.

```bash
bash scripts/preflight-server.sh /path/to/work
python3 scripts/prepare_reference.py --lock /private/config/reference.lock.json --root /private/work/references --execute
python3 scripts/prepare_all_resources.py --root /private/work --execute
python3 scripts/workflow.py --help
python3 scripts/annotation_stages.py --help
python3 scripts/export_cohort_sample_views_v3.py --help
python3 scripts/review_candidate_snv_reads.py --help
```

На практике shell-файлы запускаются через `bash`, а Python — через `python3`. Перед полным запуском нужно проверить `--help` конкретной версии скрипта и записать версии всех инструментов.

## Сборка полных списков и Excel

Нужны Python 3 и `openpyxl` (`python -m pip install openpyxl`). Пути и идентификаторы в примере замените своими приватными значениями. Сборщик использует готовые входы, не выполняет вызов вариантов или новую аннотацию.

```bash
python scripts/prepare_full_cvd_views.py \
  --vcf-qc /private/cohort.quality.vcf.gz \
  --opencravat-sqlite /private/opencravat.sqlite \
  --clingen-validity-csv /private/clingen.csv \
  --vep-tables /private/cohort-tables \
  --supplementary-json /private/supplementary.json \
  --xy-quality-vcf /private/XY.quality.vcf \
  --samples SAMPLE1 SAMPLE2 SAMPLE3 SAMPLE4 \
  --exclusions /private/exclusions.json \
  --output-json /private/full-views.json
python scripts/write_full_cvd_xlsx.py --input-json /private/full-views.json --output-xlsx /private/report.xlsx
```

`--samples` указывается в точном порядке образцов VCF, и этот порядок проверяется в обоих VCF. VEP-каталог должен содержать функциональные TSV.GZ с ожидаемыми столбцами. `supplementary.json` — заранее подготовленный приватный JSON с массивом `sheets`, элементами `name`, `headers`, `values` и листами `Все_исходные_кандидаты`, `X_Y_все`, `MT_все` и `MT_<имя образца>` для каждого образца. Создание этого промежуточного JSON из сырых данных в данный сборщик не входит. Лист с исходными кандидатами дополняет доступные частоты; X/Y и MT переносятся из подготовленных ранее результатов.

Необязательный `--exclusions` — приватный JSON-массив ключей `CHROM:POS:REF:ALT`, которые по результатам отдельной проверки исключены из сопоставления. Если в OpenCRAVAT отсутствует подходящая запись прошедшего QC варианта, сборщик останавливается; нельзя автоматически считать отсутствие безопасным. Входы, исключения, JSON и Excel содержат данные исследования и в публичный репозиторий не помещаются.

## Ограничения

Скрипты формируют воспроизводимый исследовательский конвейер. Они не выдают медицинское заключение, не заменяют подтверждение варианта, родословную, валидацию лаборатории, ACMG-review или CNV/SV-специфический pipeline. В публичную копию не включаются результаты, идентификаторы пациентов, BAM/VCF, базы данных и секреты.
